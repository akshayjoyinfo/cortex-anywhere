cortex-lite · day zero

Cortex Lite Architecture

Multi tenant AI agents on Hetzner. One codebase, three cloud servers and one GPU. Postgres row level security is the guarantee; the model is treated as hostile.

Fail closed. Right tenant's data, or no data. Never another tenant's data, whatever the model does.
1 · Folder architecture

One repo, modules inside one monolith

cortex-lite/
├─ docs/            00–14, adr/, site/ (these pages)
├─ db/              migrations/ (fail closed SQL), checks/ (CI gates)
├─ infra/           terraform/ · ansible/ · compose/  (one per server)
├─ src/
│  ├─ Cortex.Web           single executable: web | worker
│  ├─ Cortex.Core          TenantContext, middleware, tenant scoped DI
│  ├─ Cortex.Data          DbContext, set_config interceptor
│  ├─ Cortex.Agents        run loop, tool allow list, LLM gateway
│  ├─ Cortex.Worker        Hangfire jobs, signed envelopes
│  └─ Cortex.ServiceDefaults  OpenTelemetry, health
├─ tests/           Unit · Integration · Security (leak + injection) · perf/
└─ Cortex.sln       Directory.*.props at root
RuleWhy
Core references nothing; everyone references CoreTenant identity has one source
Only Data talks SQL; only Agents talks to the modelEach guardrail lives in one project
New feature = folder inside a module, not a new projectNo microservice drift
